## Contrato HTTP

No se crean endpoints. Se agrega el parametro opcional `final` al resumen:

```http
GET /api/control-costos/obras/9/resumen?final=true
```

Requiere el permiso existente `Visualizar_control_costos` y empresa activa,
incluido el administrador global en esta consulta. Devuelve 404 para obra
inexistente/ajena o sin linea base activa; 409 para obra no finalizada,
presupuesto base no aprobado o inconsistencia de totales.

La respuesta conserva `success`, `data.linea_base` y `data.resumen` de CU17.
Agrega `data.obra`, `data.resumen.costo_final_registrado` y
`data.desglose_por_categoria` (las cinco categorias de CU17, con ceros si no hay
ejecucion). Son campos de respuesta calculados, no columnas nuevas.

Sin `final=true`, el resumen conserva el comportamiento anterior. El endpoint
`GET /api/control-costos/obras/{id_obra}/comparacion` no cambia.

```http
PATCH /api/proyectos/9/estado
Content-Type: application/json

{"estado_obra": "FINALIZADO"}
```

Conserva el permiso existente `Modificar_obras`. CU32 bloquea la fila de obra,
ejecuta el SP existente sin commit independiente, verifica el estado almacenado,
calcula el resumen y confirma todo en una transaccion REPEATABLE READ. Si falla
el calculo o falta la linea base, revierte el estado. El servicio devuelve
internamente `resumen_economico_final` con los datos calculados; el router
conserva la respuesta habitual del SP y omite ese resumen. Los importes se
consultan mediante el GET con `Visualizar_control_costos`, de modo que
`Modificar_obras` no concede acceso financiero adicional.
Para el administrador global, el servicio de obras resuelve la empresa real
antes de invocar CU32. Los otros estados siguen el flujo anterior.

## HU135, HU136 y HU137

- **HU135:** suma los costos REGISTRADO de la linea base activa, excluye ANULADO
  y conserva el desglose MATERIAL, MANO_OBRA, EQUIPO, SUBCONTRATO y OTRO. No
  inserta, actualiza ni elimina costos. Verifica que el desglose coincida con CE.
- **HU136:** reutiliza P0, PR y CE de CU17. P0 es costo directo historico de las
  partidas; PR agrega solamente impactos de ordenes APROBADAS. Las variaciones
  son CE-P0 y CE-PR; los porcentajes usan la referencia correspondiente y son
  null con divisor cero. `t_estimacion.monto_total` incluye utilidad y no
  sustituye P0. Las ordenes aprobadas no se suman nuevamente a CE.
- **HU137:** consulta exclusivamente obras FINALIZADO mediante `final=true`,
  con obra, linea base, resumen de CU17, costo final registrado y categorias.

## Limites conservados

- NO ENCONTRADO: tabla de cierre historico o snapshot inmutable. El resumen
  se recalcula desde los datos vigentes. CU17 puede seguir modificando costos
  y ordenes; no se introducen reglas nuevas de bloqueo financiero.
- Sin costos, CE y categorias son cero; el contador existente
  `total_costos_registrados` permite distinguir que no hay registros. No prueba
  que la obra no haya tenido gastos reales.
- Las nuevas partidas de ordenes aprobadas siguen la limitacion de CU17:
  aumentan PR, pero no admiten registro de ejecucion contra una partida nueva
  ajena a la estimacion base.
- No se imputan compras, inventario, personal o asignaciones de maquinaria
  como gastos adicionales. No se calcula utilidad/perdida comercial.
- La definicion desplegada de `sp_actualizar_estado_obra` no esta en las
  migraciones disponibles; se reutiliza su contrato actual y se verifica
  posteriormente el estado real en la misma conexion.
- Las lecturas usan un snapshot consistente, no un bloqueo de todas las
  escrituras financieras concurrentes. No es un cierre contable inmutable.
- La bitacora conserva el flujo existente posterior al commit del estado.
  No forma parte de la transaccion de CU32.
